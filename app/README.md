# Smart Poultry Farm — Mobile App

Flutter app (Android and iOS) for monitoring and controlling the ESP32 poultry-house controller through Firebase Realtime Database. English and Arabic, light and dark themes, push notifications, and a vision-AI monitoring tab.

## Setup

Requirements: Flutter 3.x stable, a Firebase project with Realtime Database and Anonymous Authentication enabled.

```bash
cp .env.example .env          # fill in your Firebase values
flutterfire configure         # writes lib/firebase_options.dart + android/app/google-services.json
flutter pub get
flutter run
```

`flutterfire configure` needs the Firebase CLI (`npm i -g firebase-tools`, then `firebase login`). Without it you can edit `lib/firebase_options.dart` by hand with the values from the Firebase console.

Push notifications use OneSignal. Put your OneSignal App ID in `lib/core/services/push_notification_service.dart`; the same App ID and the REST API key go into the firmware's `secrets.h`. The Android notification channel `farm_alerts` is created in `android/app/src/main/kotlin/.../MainActivity.kt` and must keep the same id as `ONESIGNAL_ANDROID_CHANNEL_ID` in the firmware, otherwise alerts silently fall back to a private channel and lose their lock-screen text.

Release build for testers (single ABI keeps the build light):

```bash
flutter build apk --release --target-platform android-arm64
```

## Project structure

```
lib/
├── main.dart, app.dart              Entry point, MaterialApp, theme + locale wiring
├── firebase_options.dart            Generated by flutterfire (per project)
├── core/
│   ├── models/                      SensorLatest, ControlState, FanCycleConfig,
│   │                                DeviceMetadata, SensorThresholds, Alert, vision types
│   ├── providers/                   Firebase root + alert streams, locale
│   ├── services/                    Vision alarm engine, alert localisation,
│   │                                OneSignal init, database seeder
│   ├── theme/                       Light/dark ThemeData + persisted toggle
│   ├── utils/bidi.dart              RTL-safe numeric ranges
│   └── widgets/                     Startup gate (Firebase init), notification badge
├── features/
│   ├── devices/                     Dashboard, settings, device card, threshold widgets,
│   │                                DeviceRepository (all reads/writes to farm/)
│   ├── provisioning/                WiFi setup wizard talking to the ESP32 portal
│   └── vision/                      AI Monitor tab + VisionRepository
└── l10n/                            app_en.arb, app_ar.arb → generated AppLocalizations
```

State management is Riverpod. There is no router: the app is single-farm, single-device, and every screen is reached from the dashboard's bottom navigation.

## How the app talks to the controller

- **Reads** stream from `farm/sensors/latest`, `farm/control/state`, `farm/meta`, `farm/config/*` and `farm/alerts`.
- **Writes** go to `farm/control/state` (partial `update`), `farm/config/thresholds`, `farm/config/fanCycle`, and alert acknowledgements. The repository applies the same guards the firmware does, so a toggle that the device would reject is never sent.
- **Online** means `meta.lastSeen` (or the latest sensor timestamp) is fresh. The firmware heartbeats every 10 s.
- **History**: the ESP32 only writes `sensors/latest`. This app appends each new reading to `farm/sensors/history/{YYYY-MM-DD-HH}/` so trends can be charted later.
- **App Control** is a toggle that hands control ownership between the app and the LCD. The device ignores it automatically whenever it cannot reach the cloud.

Field names are shared string contracts with the firmware. See `docs/FIREBASE_SCHEMA.md` at the repository root before renaming anything.

## Vision AI tab

An external desktop analyzer ("GallineX") writes a single snapshot to `PoultrySystem/vision/analysis`. The app logs each new snapshot to `farm/vision/history`, evaluates alarm rules in `vision_alert_engine.dart` (a faithful port of `vision_alerts_prototype/`), and raises alerts into the same `farm/alerts` list the firmware uses, tagged `deviceId: "vision-ai"`.

## Tests

```bash
flutter test
```

Unit tests cover model parsing, the online window, provider guards and the firmware-mirroring safety rules; widget tests cover startup and the notification badge.

## Localisation

Strings live in `lib/l10n/app_en.arb` and `app_ar.arb`; `flutter gen-l10n` (run automatically by `flutter pub get`) regenerates `app_localizations*.dart`. Numeric ranges embedded in Arabic text are wrapped with directional isolates (`core/utils/bidi.dart`) so "18-24" does not render reversed.
